# Датасет Ани

Зафиксированный пакет: **1000 train / 100 validation / 100 test / 1 diagnostic**.
Всего 4804 целевых PNG, 128×128, режим L, 8 бит. Цель — амплитуда `png/255`.
Файлы `01…04.png` соответствуют 24,1 / 25,3 / 26,5 / 27,7 мм.
Тестовые примеры не используются в обучении или выборе checkpoint.

## Файлы

- `generate_dataset.py` — воспроизводимый генератор v0.2.0; по умолчанию 1000 train.
- `diagnostic_source/` — исходная четвёрка А1 для воспроизведения.
- `data/manifest.json` — единственная точка входа загрузчика, пути относительно манифеста.
- `data/{train,validation,test,diagnostic}/` — готовые изображения.
- `audit.py` — независимый аудит фактических файлов и приблизительный поиск похожих изображений.
- `../../reports/dataset_audit.json` — текущий полный аудит; `../../reports/near_pairs.png` — близкие пары.
- Корневой `requirements.txt` и `uv.lock` фиксируют зависимости, включая Pillow 13.0.0.

Семейства: геометрия, цифры 0–9, латинские A–Z, простые пиктограммы,
ломаные, композиции. Есть чёткие и размытые цели, плавная неоднородность яркости.
Это вариации желаемой амплитуды, не физическая модель лазерных помех.

## Запуск из корня репозитория

Окружение проекта: `uv sync --frozen --group dev`.
Команды ниже явно задают `PYTHONPATH=src`, включая дочерние процессы тестов.

Проверить загрузку готового пакета:

```bash
PYTHONPATH=src uv run python -c "from model.data_connector import load_manifest; d=load_manifest('src/dataset/data/manifest.json'); print(d.report.counts, d.report.warnings)"
```

Запустить аудит (папка отчёта должна быть новой):

```bash
PYTHONPATH=src uv run python -m dataset.audit --manifest src/dataset/data/manifest.json --out runs/dataset/audit_1000
```

Воспроизвести пакет в новой папке, затем проверить все исходные пиксели:

```bash
uv run python src/dataset/generate_dataset.py --train 1000 --out runs/dataset/reproduced
PYTHONPATH=src uv run python -m dataset.audit --manifest runs/dataset/reproduced/manifest.json --reference src/dataset/data/manifest.json --out runs/dataset/audit_reproduced
```

Тесты проверяющего кода и интеграции:

```bash
PYTHONPATH=src uv run pytest src/tests/test_dataset_audit.py src/tests/test_connector.py
```

Если окружение уже активировано, вместо `uv run python` используйте `python`.
Генератор не перезаписывает существующие папки. Для точного повторения сохраняйте
код, seed=3701 и версию Pillow. Увеличение train не меняет старые примеры v0.2.0.
Изменение самого распределения генератора требует новой версии набора и сравнения.

## Как читать аудит

`failed` / код возврата 2 — ошибка структуры, отсутствующий файл, точный дубликат,
нарушение формата/полей или изменение замороженных данных. Обучение такого пакета остановить.

`review_required` / код 0 — жёстких ошибок нет, есть ограничения распределения или
подозрительно похожие пары. Нужно прочитать предупреждения и посмотреть панель.
`passed` / код 0 — проверяемых ошибок и предупреждений не найдено; это всё равно
не гарантия качества модели или отсутствия всех возможных похожих изображений.

Хеши считаются по реальным пикселям всех файлов, а не копируются из прежнего отчёта.
С `--reference` перечитываются все исходные изображения; проверяются также записи
и неизменность состава validation/test/diagnostic. Статистика считается по изображениям
без общего массива float64. Поиск похожести приближённый: кандидаты по 32×32,
проверка пяти лучших по Пирсону на 128×128; все val/test и выборка 300 train.
Порог 0,95 — диагностическое соглашение, не официальный критерий лаборатории.
Нет инвариантности к сдвигам/поворотам, и поиск может пропустить близкие пары.

Не удаляем похожие тестовые картинки после просмотра результата модели. Для
исследования нового распределения делаем отдельно версионированный набор.
Тысяча четвёрок — рабочий бюджет хакатона, достаточность подтверждают кривые
валидации и сравнение с baseline, а не число файлов само по себе.

## Дополнительные полутона

`expand_grayscale.py` создаёт отдельно версионированное расширение, не изменяя
исходный набор. Команда из корня:

```bash
uv run --frozen python -m dataset.expand_grayscale --out build/data_gray --extra-train 1000 --stress-count 100
```

Добавляет 1000 train-четвёрок с независимым выбором шести новых типов полутоновых
целей на каждой плоскости и отдельные 100 stress-validation. Новый train содержит
2000 четвёрок. Сохраняет исходные PNG и записи без изменений. Проверяет формат,
точные дубли и хеши исходных пикселей, пишет `grayscale_report.json`.
`stress/manifest.json` не смешивается с обучающими данными и исходной validation.
Этот пакет имеет другой контракт яркости: серый фон допустим. Поэтому прежний
аудитор `dataset.audit`, проверяющий чёрный фон и поля, для него не предназначен;
проверка выполняется `dataset.expand_grayscale.verify`.

При новой генерации исходный генератор также создаёт previews и validation_report.json;
для обучения они не нужны. Актуальные отчёты готового пакета собраны в корневом reports/.

А2 — ДАТАСЕТ АНИ ДЛЯ МАКСИМА

ГОТОВЫЕ ДАННЫЕ УЖЕ ЛЕЖАТ В data/. ПЕРЕД ОБУЧЕНИЕМ ГЕНЕРИРОВАТЬ ИХ ЗАНОВО НЕ НУЖНО.

Объём: 200 train + 100 validation + 100 test + 1 diagnostic.
Это 401 четвёрка, 1604 отдельных целевых PNG. Не 200 одиночных картинок.
Все цели: PNG, 128×128, режим L, 8 бит, светлый сигнал на чёрном фоне.
Цели интерпретируются как нормированная амплитуда png/255.

Формат согласован с присланными HANDOFF.md и to_anya.md Максима:
data/manifest.json: format=doe-manifest/1; относительные пути;
в каждой записи sample_id, split, images, distances_mm, seed, params, generator_version.
Каналы неизменны: 01.png -> 24.1 мм, 02.png -> 25.3 мм,
03.png -> 26.5 мм, 04.png -> 27.7 мм.
Диагностика А1 сохранена без изменения пикселей, отдельным split=diagnostic.

СОДЕРЖАНИЕ

Шесть сбалансированных семейств:
1. Геометрия: круг, кольцо, прямоугольник, треугольник, крест, эллипс,
   ромб, звезда, пятиугольник, группы пятен.
2. Цифры 0–9.
3. Латинские заглавные буквы A–Z.
4. Простые пиктограммы: дом, дерево, сердце, стрелка, чашка, флаг, солнце, облако, лодка.
5. Случайные толстые ломаные со скруглёнными соединениями.
6. Композиции из 2–3 геометрических фигур/пиктограмм, с возможным перекрытием.

Это первый ограниченный процедурный набор, не генератор любой возможной картинки.
Кириллицы, фотографий и реалистичных предметов в этой версии нет.
Один встроенный в Pillow шрифт; системные шрифты и загрузки из интернета не нужны.
Все изображения создаются заново кодом. Семейства фигур общие для train/val/test:
проверяется перенос на новые экземпляры этих семейств, а не на неизвестные классы.

Вариации: положение, размер, небольшая деформация пропорций, поворот,
толщина линий у соответствующих фигур, число пятен, композиции объектов.
У букв и цифр поворот ограничен примерно ±22 градусами.
Класс объекта не привязан к расстоянию; порядок семейств случайно перемешивается
внутри каждой четвёрки, но порядок самих файлов относительно расстояний фиксирован.

КОНТРОЛИРУЕМАЯ «РАССЕЯННОСТЬ»

Приблизительно 25% целей чёткие, 50% с мягкими краями, 25% с мягкими краями
и плавной неоднородностью яркости внутри объектов. Точные доли случайны;
фактическое распределение записано в data/validation_report.json.
Размытие Gaussian: sigma от 0.45 до 1.65 пикселя в зависимости от режима.
Все изображения сначала рисуются в 512×512 и уменьшаются до 128×128
с антиалиасингом. Даже чёткий режим имеет аккуратно сглаженный край.

Это художественные/численные вариации целевого сигнала, а НЕ физическая
модель рассеяния лазера. Оптические перекрёстные помехи возникают в симуляторе
при восстановлении из ДОЭ. Добавление случайного шума в цели само по себе
не исправляет физику и не гарантирует более устойчивую модель.
В этом пакете не добавляем сильный белый шум или фоновые точки по всему кадру:
сохраняем читаемый объект и чёрный фон, как просил Максим.
Сами PNG уже являются окончательными целями — их сравниваем с восстановлением.
Отдельных пар «испорченный вход — чистая цель» нет: это не обучение удалению шума.

ПЕРЕДАЧА МАКСИМУ

1. Передать весь архив или папку data целиком. Отдельные картинки без манифеста
   передавать не надо. previews/ — панели для просмотра, они не входят в samples.
2. В корне проекта Максима поместить data/manifest.json и папки сплитов в data/.
   Если data уже существует, сначала сохранить её отдельной копией; не смешивать
   разные версии датасета и не удалять существующие данные вслепую.
3. Проверить именно загрузчиком проекта (пакет doe_synth уже должен быть установлен):

.venv/bin/python -c "from doe_synth.data import load_manifest; d=load_manifest('data/manifest.json'); print(d.report.counts, d.report.warnings[:5])"

Ожидаемые количества: diagnostic=1, train=200, validation=100, test=100.
Исходников doe_synth в присланных документах нет, поэтому здесь выполнена
независимая проверка формата; фактический вызов загрузчика выполняет Максим.

4. Порядок обучения из TRAINING_METHODS.md: train_smoke на 8 четвёрках из train,
   затем v1. Checkpoint выбирается по validation. Test не использовать для
   подбора настроек; оценивать один раз после фиксации модели.
5. Дополнительные аугментации применять только в train. Если они включены,
   при перестановке каналов получаем новую целевую четвёрку; файлы исходного
   датасета и манифест при этом не переписывать.

ПРОВЕРКИ

Проверены все 1604 PNG: формат, режим, размер, наличие объекта и фона,
ненулевая дисперсия, порядок z, уникальные ID и пиксельные SHA-256.
Точные дубликаты изображений запрещены во всём пакете, включая diagnostic.
Это сильнее требования запрета дубликатов между сплитами.
Программно проверены поля вокруг видимого сигнала; объекты целиком в кадре.
Четыре панели previews/contact_sheet_01.png ... 04.png показывают 20 четвёрок:
10 train, 5 validation, 5 test. Их нужно просматривать как проверку данных,
не использовать вид тестовых целей для подбора архитектуры и параметров.

Процедурные примеры в разных сплитах независимо рисуются из отдельных seed,
а не получаются аугментацией общих исходных PNG. У них могут встречаться
похожие буквы или геометрические формы — это ожидаемо. Проверка точных
дубликатов не доказывает отсутствие всех визуально похожих экземпляров.

ВОСПРОИЗВЕДЕНИЕ ДЛЯ АНИ НА MAC

Распаковать архив. В терминале перейти в папку a2_dataset, где лежит этот файл.
Если есть активное окружение, можно использовать его. Иначе:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

Проверить готовые файлы:

python generate_dataset.py --verify data/manifest.json

Пересоздать тот же пакет в НОВОЙ папке:

python generate_dataset.py --out data_reproduced

Увеличить только train до 1000 четвёрок, сохранив seed=3701 и размеры val/test:

python generate_dataset.py --out data_1000 --train 1000

Не менять --seed и код генератора при таком расширении.
Первые 200 train, вся validation, test и diagnostic сохраняют те же пиксели.
Все остальные тренировочные примеры добавляются в конец train.
Генератор отказывается писать в существующую папку, защищая замороженные данные.
Манифест большего набора получает новую dataset_version; нельзя подменять
данные старой версии незаметно. Для сравнения версий есть пиксельные хеши
в validation_report.json. Воспроизводимость требует одинаковой версии Pillow.

ФАЙЛЫ

generate_dataset.py — генератор и независимая проверка готового манифеста.
requirements.txt — точная версия Pillow для воспроизведения.
diagnostic_source/ — четыре исходных PNG А1; нужны для генерации.
data/ — готовый пакет для обучения.
data/validation_report.json — отчёт проверок и хеши изображений.
data/previews/ — визуальные панели, не обучающие входы.
reproducibility_check.json — результат повторной генерации и проверки расширения.
message_to_maxim.txt — готовый текст передачи.

Сеть, фазовые маски и физические восстановления в этот пакет не входят.

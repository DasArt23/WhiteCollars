# Soft600: пакет для повторного обучения

Новая отдельная версия: **600 train / 100 validation / 100 test / 1 diagnostic**.
Это 3204 целевых PNG; 600 — число обучающих четвёрок, а не тестовых картинок.
Старый `data/` сохранён без изменений. Начинать с `data_soft600/manifest.json`.

## Почему изменили данные

У старого набора были не только резкие края: многие объекты занимали очень
малую часть кадра, а четыре независимые цели не обязаны быть достижимы одной
фазовой маской. Простое размытие не устраняет это ограничение.

Архив, предоставленный Аней для сравнения, согласно его README содержит
256 четвёрок из фазового моделирования и 256 процедурных. Он использовался
для анализа подхода, но **чужие PNG, фазы и код в этот пакет не включены**.
Новые изображения воспроизводятся нашим кодом и собственными seed.

## Состав и смысл двух групп

| Группа | Train | Validation | Test | Что получает сеть |
|---|---:|---:|---:|---|
| `soft_independent` | 360 | 60 | 60 | Четыре независимо нарисованные мягкие цели |
| `physical_forward` | 240 | 40 | 40 | Четыре восстановления от одной сохранённой маски |

`soft_independent`: геометрия, цифры 0–9, латинские буквы A–Z, пиктограммы,
ломаные и композиции. Объекты крупнее прежних; утолщены тонкие штрихи;
размытие 1,4–3,2 пикселя; вариации положения, пропорций, поворота, плавной
яркости. Дефекты — локальные плавные ослабления/выемки, а не белый шум поверх
чистой цели. В train: 587 мягких чистых, 460 с неоднородной яркостью,
393 с дефектами, всего 1440 процедурных изображений. Яркая область каждого
занимает минимум 6% кадра. Отступ видимого сигнала от края минимум 4 пикселя.
Все 15 сочетаний четырёх из шести семейств используются, семейство не
закреплено за плоскостью. Один встроенный шрифт; поддержка произвольных
фотографий, русского алфавита и любых объектов не заявляется.

`physical_forward`: сначала создаются четыре мягких пожелания к изображению,
существующий многоплоскостной GS за 40 итераций получает фазу; фаза сохраняется
в 8-битный PNG и перечитывается. **Финальные цели — реальные численные
восстановления из этой фазы**, включая дифракционную зернистость и фон.
Они могут заметно отличаться от пожеланий. После восстановления не добавляются
размытие, обрезание, шум или вычитание фона. Так у каждой четвёрки есть
подтверждение достижимости в принятой численной модели с точностью до PNG.
Это не гарантия достижимости на реальном стенде и не гарантия качества сети.

Зернистость здесь физически рассчитана; она не имитирует параметры конкретной
камеры. Края поля и ненулевой минимальный пиксель разрешены только для
явно помеченной группы `physical_forward`. Для обычных фигур прежние
проверки чёрного фона и отступов сохранены.

## Оптический и файловый контракт

- PNG 128×128, L, 8 бит; вход `PNG/255` — нормированная амплитуда |U|.
- `01.png` → 24,1 мм; `02.png` → 25,3; `03.png` → 26,5; `04.png` → 27,7.
- Длина волны 532 нм, шаг DOE 10 мкм, равномерное освещение.
- Реализация — существующий однократный FFT Френеля в `doe_eval.physics`.
  Масштаб сетки наблюдения зависит от z: λz/(128·10 мкм).
- Фаза кодируется по существующему правилу 0 → −π, 255 → +π.
- В каждой папке целей только четыре PNG. Контрольные фазы вынесены
  в `reference_phases/`; их нет в `images` манифеста.
- `params.kind` обозначает группу. `params.targets` у физических примеров
  описывает исходные пожелания; это НЕ описание чистых эталонов для denoising.
- `origin_id`, seed, параметры объектов и дефектов записаны в манифесте.
  Варианты одного исходного примера не распределяются между split.

## Максиму: как подключить

Из корня репозитория, после получения актуального `sandbox`:

```bash
uv sync --frozen --group dev
PYTHONPATH=src uv run python -c "from model import load_manifest; d=load_manifest('src/dataset/data_soft600/manifest.json'); print(d.report)"
```

В обучающем Python-коде заменить путь к манифесту:

```python
from model.data_connector import build_dataloaders

loaders = build_dataloaders(
    manifest_path='src/dataset/data_soft600/manifest.json',
    batch_size=8,             # уменьшить, если не хватает памяти
    num_workers=0,            # удобный первый запуск на Mac/Windows
    augment_train=False,
    pin_memory=False,        # для CUDA можно включить
)
targets, sample_ids = next(iter(loaders['train']))
assert targets.shape[1:] == (4, 128, 128)
```

Никакой новый CLI обучения не выдуман: архитектуру, optimizer и цикл обучения
берём из рабочего кода Максима. В проверенной ветке доступен коннектор;
результаты обучения конкретной модели этим пакетом пока не получены.

Порядок действий:

1. Проверить загрузку; отключить произвольную перестановку каналов, вращения,
   отражения, изменение размеров и шумовые аугментации. Для физических
   примеров перестановки/геометрические аугментации коннектор отклоняет:
   сохранённая фаза больше не подтверждала бы такую изменённую четвёрку.
2. Сначала попытаться переобучить модель на 4–8 примерах **из train**.
   Для известной контрольной фазы проверить физический проход отдельно:
   её восстановление должно совпасть с целями; это проверка кода, не сети.
3. Если loss не снижается даже на нескольких примерах, проверить конечные
   ненулевые градиенты, единицы z, порядок каналов, amplitude/intensity,
   нормировку, размер и диапазон фазы. Простое добавление данных это не чинит.
   Не делать `.detach()`, NumPy/PIL round-trip или обычное округление в середине
   обучающего прохода: используйте существующий дифференцируемый путь/STE.
4. Затем обучить на 600 train, checkpoint и настройки выбирать по validation.
   Отдельно записывать качество обеих групп. Не сводить всё к одной красивой
   средней цифре. Само по себе число 600 не гарантирует достаточность данных.
5. По желанию использовать отдельные `manifest_soft_independent.json` и
   `manifest_physical_forward.json`: они ссылаются на те же изображения и
   сохраняют исходные split; это не дополнительные данные.
6. Test оценить после фиксации модели/настроек. Старый test остаётся отдельным
   сравнением переноса на более резкие/мелкие независимые цели; не переименовывать
   его и не включать в новый train. Старый test может уже быть знаком команде,
   поэтому его нельзя заново объявлять полностью слепым.
7. Baseline и neural сравнивать на одних и тех же целях, с одним физическим
   проходом и метриками. Для финального теста использовать сохранённый/
   перечитанный DOE PNG и восстановленные PNG по контракту проекта.

**Контрольную фазу запрещено выдавать за предсказание сети.** Она служит для
проверки достижимости и отдельно описанного обучения с учителем, если Максим
решит его реализовать. В текущем загрузчике она не поступает на вход модели.
При таком дополнительном обучении брать только train-фазы; обычный MSE по
обёрнутой фазе некорректен у границы −π/+π и не учитывает неоднозначность фазы.

## Проверка и воспроизведение

Окружение зафиксировано `uv.lock`, точные версии и хеши исходников — в манифесте.
Генерация использует CPU; одинаковые seed и окружение воспроизводят пиксели.
Между версиями Pillow/PyTorch и платформами битовая идентичность не обещается.
Расширение train не меняет первые train и фиксированные validation/test.

```bash
PYTHONPATH=src uv run python -m dataset.generate_soft_dataset --out runs/soft600_reproduced --train 600 --validation 100 --test 100
PYTHONPATH=src uv run python -m dataset.audit_soft_dataset --manifest src/dataset/data_soft600/manifest.json --old-manifest src/dataset/data/manifest.json --out runs/soft600_audit.json
PYTHONPATH=src uv run pytest src/tests/test_soft_dataset.py src/tests/test_dataset_audit.py src/tests/test_connector.py
```

Генератор и отчёты не перезаписывают существующие пути. Если команду запускают
повторно, указать новую папку. `requirements.txt` старого генератора с одним
Pillow недостаточно для новой версии: нужны зависимости всего проекта.

Проверки: точные дубликаты всех целевых изображений, пересечения со старым
набором, режим/размер/порядок, seed и origin, SHA256 файлов, сохранённые фазы,
соответствие каждой физической четвёрки своей фазе. Три train-примера дополнительно
проверяются независимым NumPy-расчётом через матрицу ДПФ.

Поиск похожих изображений приблизительный: top-5 по уменьшенному изображению
с проверкой на 128×128, все запросы validation/test и 300 train-запросов.
Он не является доказательством отсутствия семантически одинаковых фигур.
Круги/одинаковые символы будут повторяться как классы — это нормально.
Предупреждения сохраняются честно; отчёт не является внешним «сертификатом».

## Как интерпретировать метрики

В проекте сейчас есть глобальный SSIM и оконный SSIM — это разные метрики,
их нельзя смешивать под одним названием. Наш небольшой контроль использует
оба существующих метода, Пирсон, единый GS60 и первые 12 train-примеров
каждой группы; test для настройки генератора не использовался.
Подробности и результаты: [soft600_report/SUMMARY.md](soft600_report/SUMMARY.md).

Большие метрики на другой, более согласованной задаче не доказывают улучшение
нейросети. У физических целей проверка с собственной исходной фазой по
построению почти идеальна — она НИКОГДА не включается в таблицу качества neural.

Полезный научный ориентир: [Neural Holography, Peng et al., SIGGRAPH Asia 2020](https://www.computationalimaging.org/wp-content/uploads/2020/08/NeuralHolography_SIGAsia2020.pdf).
В работе обучение связано с прямым распространением рассчитанной фазы и
сравнением амплитуд. Здесь используется собственный генератор и физический
код команды; экспериментальная калибровка из статьи нами не реализована.

# Сверка с PROMPT.md, ТЗ и дополнительными правилами сдачи

Проверены исходники `src/`, тесты, зависимости, Makefile, документация, данные
и текст презентации. Исходное ТЗ требует фазовый ДОЭ и single-FFT Френель;
PROMPT.md описывает проверяющий модуль, а не доказанно лучший метод обучения.
Обучение модели в этой сессии **не запускалось**.

## Исправленные расхождения

| Область | Изменение и причина |
|---|---|
| Физика | Константные оптические фазы вычисляются в float64 и кешируются в complex64: float32 терял точность большого угла kz. Центрированные FFT, шаг λz/(N·PIXEL) и батчи сохранены. |
| Обратное распространение | Сеть и GS используют один inverse с полным префактором. Прежний оператор сети компенсировал только фазу и иначе масштабировал плоскости; ошибочное название «adjoint» исправлено. |
| Независимость эталона | Импорт NumPy-эталона больше не импортирует physics/torch через __init__. Эталон использует явные матрицы ДПФ. |
| SSIM | Исправлен обучающий оконный SSIM: дополнительный epsilon в знаменателе занижал совпадение тёмных окон. Проверено соответствие skimage, включая чёрные/белые и разреженные изображения. |
| Пирсон | Согласован случай констант в NumPy/PyTorch; устранено подавление корреляции малоконтрастных изображений из-за абсолютного epsilon. |
| Loss | Убран второй лишний прогон всей физики. Добавлена проверка конечности loss; AMP-пропуск обновления не сдвигает scheduler. |
| Checkpoint | Согласно дополнительным правилам SSIM основной: после уточнения о визуальной оценке выбор производится по гармоническому среднему SSIM skimage и положительного Пирсона; при равенстве — по SSIM. Это внутренняя эвристика, официальные метрики не изменяются. Глобальный SSIM тоже пишется в журнал. Seed, хеш manifest и критерий сохраняются. |
| Уточнение фазы | Проверяются начальная фаза и последний шаг, лучший кандидат выбирается для каждого примера по совместному критерию Пирсона и оконного SSIM, как и checkpoint. Loss остаётся комбинацией трёх метрик и штрафа фона. |
| Прогноз | Отсутствующие/несовместимые веса вызывают ошибку; случайная сеть больше не подменяет обученную. Финальное восстановление проходит реальный PNG roundtrip. |
| Данные | Исправлены ID папок, поддержаны manifest/split и имена 1…4 / 01…04. Явные имена файлов учитываются. Добавлены проверки порядка каналов. Реальный датасет больше не пропускается тестом из-за устаревшего пути. |
| Загрузка | Единый контракт PNG L N×N. Убрано необоснованное требование чёрного фона у входов модели — серый фон допустим по ТЗ. NaN/Inf не записываются в PNG. |
| Аугментации | Seed загрузчика фиксируется; у разных workers независимые генераторы перестановки каналов. Validation/test не аугментируются. |
| V100 | Добавлен профиль PyTorch 2.10.0+cu126 и новый lock. Исходная сборка 2.15+cu132 не поддерживает Volta. Добавлена проверка реальных FFT/backward/AMP на GPU. |
| Сдача | Добавлены Dockerfile, .dockerignore, экспорт requirements.txt и команды контейнера. Веса должен получить пользователь обучением до сдачи. |
| Документация | Восстановлен RUN.md, добавлены команды обучения/оценки/сравнения методов и SVG-схема оптического восстановления. Старая презентация с неподтверждёнными цифрами удалена при очистке проекта. |

Поддержка V100 проверена по [официальной матрице PyTorch](https://github.com/pytorch/pytorch/blob/main/RELEASE.md).
Фактический запуск на GPU в этой среде невозможен: CUDA-устройства нет.

## Датасет и расширение

Повторно прочитаны все **4804 исходных изображения**: PNG L 128×128, точных
дубликатов нет, ошибок аудита нет. Статус `review_required` относится к ограничениям
распределения и похожим изображениям, а не к повреждению файлов.
Полный машинный отчёт: [reports/dataset_audit.json](reports/dataset_audit.json).

Подтверждены ограничения исходного набора: три сочетания семейств внутри train-четвёрок,
большая доля разреженных светлых объектов на чёрном фоне, несколько близких пар
между сплитами. Это процедурные данные, не доказательство обобщения на фотографии.

Добавлен воспроизводимый генератор полутонового расширения. Создан новый пакет
`build/data_gray`: **2000 train / 100 исходных validation / 100 исходных test / 1 diagnostic**
и **100 отдельных stress-validation**. Все исходные PNG скопированы побайтно,
состав и записи validation/test не менялись. Все 9204 PNG проверены на формат,
точные дубли и сохранность исходных пикселей. У новых изображений медиана — 241
уровень серого. Отчёт: [reports/grayscale_expansion.json](reports/grayscale_expansion.json).

Новые семьи: фигуры разной яркости, пятна, полосы, градиенты, гладкие текстуры и
плотные композиции; семья выбирается независимо для каждой плоскости. Серый фон
допустим. Stress-цели не участвуют в обучении или выборе checkpoint. Это расширяет
проверяемое покрытие; улучшение SSIM и обобщения необходимо подтвердить обучением.

Готовые производные данные лежат в игнорируемом `build/`; для сервера воспроизведите
их командой из RUN.md. Исходный пакет в `src/dataset/data` не изменён.

## Измеренный ориентир точности

**GS-200 на всех 100 исходных validation-четвёрках**, четыре плоскости, amplitude/max,
восстановление из сохранённых 8-битных ДОЭ, CPU PyTorch 2.15.0:

| Метод | Пирсон | SSIM global | SSIM skimage 7×7 |
|---|---:|---:|---:|
| Случайная фаза | 0,00025 | 0,00465 | 0,00120 |
| GS, 200 итераций | 0,56571 | 0,38957 | 0,12668 |

[JSON со статистикой](reports/baseline_validation.json),
[CSV по каждой четвёрке](reports/baseline_validation.csv).
Это исходная линия сравнения, не потолок физически достижимого качества и не
прогноз обученной сети. Первые 10 примеров дали другие средние — выбирать только
удачные примеры нельзя. Время в JSON измерено на CPU и не характеризует V100.

Обе метрики ограничены сверху 1. Достижимость этой границы для каждой конкретной
четвёрки не установлена: четыре поля связаны одной фазовой маской. Отдельная
оптимизация фазы тоже даст только найденный результат, а не доказательство
глобального максимума. Распределение закрытых комплектов организаторов неизвестно.

## Проверки и открытые ограничения

Регрессии покрывают независимую комплексную сумму Френеля и inverse roundtrip,
линзу, квантование/PNG, метрики и градиенты, настоящий forward/backward сети,
лучший шаг уточнения, checkpoint, CLI baseline→PNG→reconstruct, реальные данные
и воспроизводимость расширения без изменения исходных сплитов.

Итог `make check` на CPU в окружении PyTorch 2.10.0+cu126: **38 тестов пройдено**,
selfcheck: относительная ошибка с NumPy 1,12×10⁻⁷, короткое GS-демо пройдено.
`ruff check src` и `git diff --check` также пройдены. Обучение не запускалось;
checkpoint для сдачи пока не создан. Dockerfile подготовлен, но доступ к локальному
Docker-демону запрещён и сборка контейнера здесь не подтверждена.

Основные допущения: плоское единичное освещение, single-FFT Френель без множителя
площади пикселя, амплитуда и max-нормировка каждой плоскости, зависимый от z шаг
выходного пикселя, float-метрики из 8-битного ДОЭ. Основной SSIM у организаторов
не специфицирован по окну: здесь для выбора весов используется skimage 7×7 вместе с Пирсоном,
параллельно считается глобальная формула. До уточнения нельзя считать этот выбор
подтверждённым официальным протоколом.

Очистка по запросу пользователя: удалены пустой пакет app, необязательный Gradio-интерфейс,
старая презентация, дублирующие отчёты/requirements и промежуточные результаты benchmark.
Сохранены текущие отчёты и панель близких пар в reports/. Основные данные не изменены.

После разъяснения организаторов о визуальной проверке добавлены панели целей/реконструкций
в preview/ и совместный критерий выбора checkpoint/уточнения. Он предпочитает
пример P=0,566/SSIM=0,127 варианту P=0,1/SSIM=0,84; это снижает риск вырожденных
решений, но не является общей защитой от всех артефактов или заменой осмотра изображений.
